# Исправления аудита — 1.16

Выполнены по поручению от 02.10.2026. Номера соответствуют первоначальному аудиту.

| Пункт | Изменение |
|---|---|
| 1, 2 | Повторяющиеся позиции суммируются до проверки доступного количества. Нельзя принять из цеха или погрузить больше остатка за счёт двух одинаковых строк. |
| 3 | Отправленные документы и остатки частичной передачи нельзя физически удалять. Корректировка проводится через приёмку и существующий разбор расхождения. |
| 7 | Оплата имеет уникальный ключ действия. Повтор запроса с тем же ключом не создаёт вторую оплату. |
| 8 | Отмена сохраняет первоначальную оплату, дату и причину отмены, роль исполнителя. Добавлена дата фактической оплаты. Отменённая оплата не уменьшает долг. |
| 9 | Ключ погрузки передаётся как JSON-массив; знак `\|` в примечании больше не ломает выбор. Старые ключи читаются для совместимости. |
| 10, 11 | Отрицательная приёмка отклоняется; обувь списывается только целыми парами. |
| 12 | Добавление и изменение справочников проверяет совпадения независимо от регистра и лишних пробелов. В базе есть уникальные нормализованные ключи. |
| 13 | Добавлены внешние ключи, проверки количеств и статусов, уникальность операции позиции. Миграция проверяет целостность отношений и прекращается при ошибке. |
| 14 | Технические ID не переиспользуются. У передач и заявок появились отдельные неизменяемые номера с собственными счётчиками и UUID. |
| 17 | Суммы и цены нормализуются до копеек, хранятся также целыми копейками; начисление и итоги оплаты складываются в копейках. Округление — до ближайшей копейки, половина вверх. Старые REAL-поля сохранены для совместимости текущей схемы. |
| 18 | Поиск справочника не завершает чужую транзакцию. Восстановление архивной записи сохраняет прежнее поведение, но фиксируется только вместе с успешным действием. Ошибка открытия транзакции не подавляется. |
| 21 | Приёмка показывает состояние сохранения и ошибку связи. Версия строки предотвращает перезапись изменений другой вкладкой; завершение приёмки ожидает сохранения. |
| 22 | Счётчик меню вычисляется агрегированным SQL, без загрузки строк каждой принятой передачи. |
| 23 | Рабочие workers не запускают миграции. Отдельный шаг `migrate.py` выполняется до их старта; миграции защищены файловой блокировкой, ошибки не скрываются. |
| 24 | Открытие новой формы не создаёт строку в базе. Документ появляется при добавлении первой позиции; удаление последней пустой позиции убирает черновик. Старые пустые черновики очищаются. |
| 25 | Убраны стили прежней бизнес-схемы, унифицирована высота общих кнопок и полей. Добавлены предварительная загрузка и переход без полной перезагрузки для страниц просмотра; после изменений кэш сбрасывается. |
| 26 | Пустой справочник открывается с одним центральным действием. Уточнены подписи складских зон и приёмки. |
| 33 | Один каталог кода `/opt/jail`, данных `/var/lib/jail`, настроек `/etc/jail.env`, одна служба `jail.service`. Инструкция соответствует серверу. Старые рабочие копии удалены; история остаётся в Git. |
| 34 | В репозитории появился набор регрессионных проверок на изолированных базах. Проверяются превышения количества, частичные передачи, начисление по снимку цены, повтор и отмена оплаты, права, целостность, номера, расхождения, пустые формы и конфликт сохранения. |

## Исключения заказчика

Пункты **4, 5, 6, 15, 16, 19, 20, 27, 28, 29, 30, 31, 32** не исправлялись. Выбор роли без пароля, текущая привязка партий и алгоритм распределения долга остаются в прежней схеме. Расчёт персональной зарплаты не добавлен.

## Проверка

17 автоматических сценариев проходят на отдельных временных базах. В браузере проверены создание из пустого справочника, переходы без полной загрузки, высота кнопок, успешное автосохранение, конфликт вкладок и отсутствие связи. Миграция выполнялась на копии рабочей базы перед переключением сайта.
